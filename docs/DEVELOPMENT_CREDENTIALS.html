Why app_user / app_password was left unchanged: the same Postgres superuser and Mongo app account are wired into Keycloak (KC_DB), the twende-ride services, the delight-store (Medusa) backend, and every backend/frontend connection string. Renaming or rotating it is a cross-project change well beyond "user logins", so it was kept as-is and documented here.
Port overlap: Grafana and the Buyer Web app are both configured on port 3000. They are not meant to run simultaneously in dev — start whichever you need, or remap one port in docker-resources/.env.
Service Bus: your apps don't log into the emulator directly — the local profile injects the connection string Endpoint=sb://localhost:5672;…;UseDevelopmentEmulator=true. Use the sa / Emul@torStr0ng!Pass2026 credentials only for the SQL Edge store (a DB tool on localhost:1433). The SA password lives in the git-ignored docker-resources/.env. To watch messages flow, open the Service Bus Explorer web UI at localhost:5235. RabbitMQ is now opt-in (profile rabbitmq, stopped) so the emulator can own the default 5672 — it's still there for twende-ride, just can't run at the same time as the emulator. Full details: docs/MESSAGING_AND_SERVICE_BUS.html and docs/AZURE_SERVICE_BUS_EXPLAINED.html.
Why these two are NOT admin / admin_password: they physically can't be. (1) The Service Bus emulator has no user login — it uses a fixed key RootManageSharedAccessKey / SAS_KEY_VALUE and bypasses auth entirely (UseDevelopmentEmulator=true). (2) SQL Server / SQL Edge hard-codes the admin username as sa (cannot be renamed to admin), and its password must satisfy SQL's complexity policy — 3 of 4 of upper/lower/digit/symbol — so admin_password (lower+symbol only) is rejected and the container won't even start. You rarely touch it: apps talk to the emulator, never to SQL directly.

⚙️ Reset & Reseed Runbook

Reproduce the credential standardization and data reseed on a fresh machine.

1. Fresh Keycloak (imports the standardized realm JSONs)

# Realm JSONs already contain admin_password + fixed secrets.
# A fresh Keycloak volume auto-imports them via `start-dev --import-realm`.
cd docker-resources
docker compose stop dev_keycloak dev_postgres
docker compose rm -f dev_keycloak dev_postgres
docker volume rm -f dev_postgres_data          # wipes realms → forces re-import
docker compose up -d dev_postgres dev_keycloak
Wiping dev_postgres_data also clears the twende-ride realm & data (shared Postgres). Only do this on a machine where that's acceptable — otherwise apply user/secret changes live with kcadm.sh as was done here.

2. Reset a Keycloak user password live (no wipe)

docker exec dev_keycloak /opt/keycloak/bin/kcadm.sh config credentials \
  --server http://localhost:8080 --realm master \
  --user admin --password admin_password

# then, per user id:
docker exec dev_keycloak /opt/keycloak/bin/kcadm.sh set-password \
  -r myticketzm --username organizer --new-password admin_password

3. Wipe & reseed MongoDB (what was run)

cd docker-resources
docker compose stop dev_mongodb && docker compose rm -f dev_mongodb
docker volume rm -f dev_mongodb_data dev_mongodb_configdb
docker compose up -d dev_mongodb        # re-runs mongodb/init-mongo.js
App collections (users, organizations, chart_of_accounts, …) are recreated by Mongock migrations and Better Auth when the backend services and Next.js apps start — bring those up after Mongo is healthy.

4. Repo's own helper

./scripts/reset-db.sh mongodb        # mongo only
./scripts/reset-db.sh --force all     # everything (destructive)

🛡️ Security Notes

Development only. The uniform admin_password credential, the checked-in client secrets, the no-auth Redis/Axon/Prometheus endpoints, and the relaxed admin password policy are all acceptable only on a local machine. Before any shared/staging/production deployment: generate unique strong secrets, restore the strict password policy on myticketzm-admin, enable auth on Redis, and move all secrets into a managed secret store — never a Git-tracked .env.
This document itself contains live dev credentials — keep it out of any public-facing build output and treat it as sensitive.
