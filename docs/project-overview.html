Event Ticketing
System

A reactive, microservices-based ticketing platform: browse and discover events, pay with mobile money, validate tickets by QR at the gate, and give organizers full control over sales and payouts.

01

What it does

Event Discovery

Browse and search events by category, location, and pricing — served by the Catalog service through a federated GraphQL API.

Ticket Purchasing

Mobile-money checkout via PawaPay across MTN, Airtel, and Zamtel, with escrow and commission handling in the Booking service.

Ticket Validation

QR-code scanning at venues confirms tickets in real time against the Booking service.

Organizer Management

Organizers create events, track sales and revenue, and request payouts; admins approve organizers and verification documents.

03

Data & eventing

A deliberate hybrid

Business data lives in MongoDB behind the reactive driver, so the WebFlux stack never blocks. Spring Modulith's event publication log, which needs a blocking JDBC driver, is isolated in PostgreSQL — the same instance that backs Keycloak. Redis handles sessions, caching, and OTP storage with TTL.

MongoDB 8 · reactive PostgreSQL 16 · modulith + keycloak Redis 7 · cache / OTP

Two event channels

Inside a service

Spring Modulith persists events to PostgreSQL before listeners run — guaranteed delivery with retry and republish on restart.

Between services

Azure Service Bus topics (catalog / booking / identity events) via StreamBridge, with dead-letter queues and exponential backoff.

04

Passwordless authentication

Keycloak 26 is the identity provider, extended with a custom Phone OTP authenticator SPI. Customers sign in with just a phone number — the code arrives on WhatsApp (preferred in Zambia) or SMS. Admins use classic username/password.

  1. 1User submits a phone number on the Keycloak login form (E.164, +260…).
  2. 2Keycloak calls the Identity service, which generates a 6-digit OTP, stores it in Redis with a 5-minute TTL, and sends it via WhatsApp or SMS.
  3. 3User enters the code; Keycloak verifies it against the Identity service, finds or creates the user, and grants the CUSTOMER role.
  4. 4Keycloak issues JWT tokens; every service validates them via JWKS and extracts roles — CUSTOMER, ORGANIZER, ADMIN, INTERNAL_SERVICE.
